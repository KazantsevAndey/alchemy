# Яндекс Маркет: как считать маржу, чтобы сходилось с закрывающими документами

Методика проверена на августе 2026 (бизнес 714498, магазины ITALCO FBY и ITALCO 2 FBS):
три независимых отчёта Маркета сведены между собой до копейки. Скрипт сверки —
`tools/ym_month_close.py`. Ежедневный расчёт в приложении (`ym_margin.py`) использует
ту же формулу, только по дате начисления, а не по акту.

## Формула

```
Гросс      = Σ «Ваша цена за товар» × «Количество»     (лист «Размещение товаров и услуг»)
Совм.акции = Σ «Скидка за участие в совместных акциях»  (листы Размещение + Буст + Средняя миля)
Услуги     = Σ «Стоимость услуги» по всем листам         (размещение, буст, доставка, средняя миля,
                                                           приём, перевод, хранение, транзит, обработка)
НЕТТО      = Гросс − Совм.акции − Услуги
Прибыль    = НЕТТО − себестоимость проданных штук
Маржа      = Прибыль / НЕТТО
```

Источник — «Отчёт о стоимости услуг маркетплейса» (`united-marketplace-services`).
Для закрытого месяца заказывать его **по дате акта** (`yearFrom/monthFrom`): это ровно
детализация акта об оказанных услугах. Для текущего месяца — по датам начисления
(`dateFrom/dateTo`); на проверенном августе оба варианта дали одинаковые цифры.

## Что с чем сходится (август 2026)

| Величина | Отчёт об услугах (акт) | Другой источник | Разница |
|---|---|---|---|
| Гросс «Ваша цена × шт» | 1 460 926,00 | Отчёт по реализации, «доставлено, без учёта скидок» FBY 673 614 + FBS 787 312 | 0,00 |
| Гросс по строкам заказ+SKU (449 строк) | 1 460 926,00 | Отчёт о платежах: платёж покупателя + баллы Маркета + баллы Плюс | 0,00 |
| Совместные акции | 593 138,00 | Отчёт о платежах: списания «Скидка за участие в совместных акциях» с датой в августе (599 814,44 − возвраты 6 676,44) | 0,00 |
| Совместные акции по строкам | 591 457,03 | те же списания по тем же 449 строкам | 0,00 |
| Услуги | 194 204,52 | Отчёт о платежах: «Оплата услуг Маркета», акт № 255254890 от 31.08.2026 | 0,00 |
| Баллы Маркета + Плюс за месяц (нетто) | — | 593 138,00 = совместным акциям | 0,00 |

Итого за август: гросс 1 460 926,00 − 593 138,00 − 194 204,52 = **нетто 673 583,48**.
Себестоимость 538 672 → прибыль 134 911, маржа от нетто 20,0 %, KPI (себес × 1,04) 16,8 %.

Разница 1 680,97 между «совместными акциями по строкам» (591 457,03) и по месяцу (593 138,00) —
скидки на «среднюю милю» по невыкупам и возвратам июльских заказов; они списаны в августе и
входят в августовский итог, но не привязаны к строкам продаж августа.

## Как устроены деньги на Маркете (важно понимать)

1. Покупатель платит около 60 % «Вашей цены». Остальное Маркет начисляет продавцу
   **баллами** («Баллы за скидку Маркета», «Баллы Яндекс Плюс»). В платежах это выглядит как
   начисление полной цены.
2. Ровно ту же сумму Маркет списывает обратно строкой **«Скидка за участие в совместных
   акциях»** (тип «Списание», с названием услуги: «Размещение товарных предложений»,
   «Буст продаж», «Доставка (средняя миля)»). За август: баллы 593 138 = списания 593 138.
3. Итог для продавца: **на руки приходит платёж покупателя минус услуги по акту**.
   Проверка: платежи покупателей за августовские доставки 866 603 − услуги 194 204,52 ≈ нетто.
4. В отчёте об услугах это замаскировано: тариф размещения показан 44,5 %, из него
   «скидка за участие в акциях» ~92 %, остаток 3 % — и эту «скидку» потом списывают.
   Поэтому «комиссия 3 %» в кабинете — иллюзия, реальные удержания 50–57 % цены.
5. «Премия за участие в совместных акциях» — бонус обратно продавцу. В августе 2026 её нет
   (отчёт по баллам, колонка «Премия»). Если появится — прибавлять к нетто.

## Чему НЕ верить

- **Отчёт о заказах** (`united-orders`), лист «Услуги и маржа по заказам»: «Доход за вычетом
  услуг Маркета» за те же 436 августовских заказов = 1 278 625 против реальных 673 583.
  Он не вычитает совместные акции. Не использовать для маржи.
- «Комиссия» и «маржа» в личном кабинете — по той же причине.
- Модель «по факту списаний» (стоимость услуги после скидки, без возврата скидки): даёт
  маржу ~60 %. Так считали до 04.09.2026, это ошибка.

## Даты и лаги

- Отчёт об услугах датируется **датой доставки** (услуга размещения оказывается при
  доставке). Заказ, оформленный 25 августа и доставленный 3 сентября, попадает в сентябрь.
- Платёж покупателя в отчёте о платежах датируется **оформлением заказа** — на 1–6 недель
  раньше. Поэтому для сверки по строкам отчёт о платежах надо брать с запасом назад
  (скрипт берёт 60 дней).
- Возвраты и невыкупы приходят позже доставки; возврат сентября уменьшит сентябрь, не август.
- Дневной отчёт за «вчера» в 07:00 МСК ещё пустой (только буст/акции): Маркет собирает лист
  «Размещение» позже, к ~11:00 он полный. Крон в 04:00 UTC всегда видит пустое «Вчера».
- Деньги переводятся по графику с задержкой около 4 недель; суммы в статусе
  «Будет переведён по графику выплат» уже зафиксированы и не меняются.

## Технические грабли

- Лист «Размещение» имеет двухэтажный заголовок: названия скидочных колонок во второй
  строке (`_headers` в `ym_margin.py`).
- SKU из Excel приходит float (`8000604002754.0`) — нормализовать (`norm_sku`).
- Заказы ЯМ идут через FBS-кампанию 149180246 «ITALCO 2»; FBY 21526273 почти пустая.
  Отчёты об услугах и платежах — общие на бизнес, кампания не важна. Отчёт по реализации —
  по кампаниям, суммировать FBY + FBS (Tookytoy — другой ИНН, у него нули).
- Лимит API: 1 отчёт в 2 минуты на каждый тип отчёта (на businessId).
- В отчёте по реализации «Продажа бизнесу» лежит отдельными колонками — суммировать с физлицами.

## Запуск закрытия месяца

```
cd /home/alchemy/alchemy
sudo -u alchemy venv/bin/python tools/ym_month_close.py --year 2026 --month 8 --user 1
```

Скачает 4–5 отчётов (~10 минут из-за лимитов), напечатает сверку с ✓/✗ и маржу,
сохранит юнитку по SKU в `data/ym_close/2026-08/ym_close_2026-08.xlsx`.
Повторный запуск с `--no-fetch` пересчитает по уже скачанным файлам.
